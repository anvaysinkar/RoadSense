# RoadSense on STM32F411 (Black Pill), STM32CubeIDE

Port of the ESP32 RoadSense v4 firmware (rules + on-device random forest).

## Files

| File | What it does |
|---|---|
| `rs_config.h` | Build switch `RS_USE_ML` (1 = loose trigger + forest, 0 = rules only) and all detection constants |
| `rs_core.c/.h` | Signal chain (jerk, heave, 1 s roughness), ABC calibration, trigger, event window, classification, output lines. No HAL calls |
| `rs_baseline.c/.h` | ABC: mean and sigma per signal, slow adaptation on normal road, sigma floor |
| `rs_ml_features.c/.h` | The 21 features of one 1.4 s event window |
| `rs_ml_model.h` | The 40-tree random forest as constant arrays (about 29 KB of flash), generated by `edge_ml/export_model.py` |
| `mpu6050.c/.h` | MPU6050 on I2C1 (PB6 SCL, PB7 SDA): 100 Hz, DLPF 44 Hz, ±4 g; bus recovery after 20 errors |
| `gps_nmea.c/.h` | NEO-6M on USART1 RX (PA10) by circular DMA; parses RMC (position) and GGA (satellites), checksums verified |
| `usb_io.c/.h` | 8 KB output buffer to USB CDC, key input from CoolTerm |
| `app.c/.h` | Glue: TIM2 100 Hz tick, sampling loop, keys, status |

## Add to the CubeIDE project

1. Copy everything in `Inc/` into the project's `Core/Inc` and everything in `Src/` into `Core/Src`
   (drag the files onto the folders in Project Explorer and choose **Copy files**).
2. `Core/Src/main.c`, inside the existing USER CODE comments only:
   ```c
   /* USER CODE BEGIN Includes */
   #include "app.h"
   /* USER CODE END Includes */
   ...
   /* USER CODE BEGIN 2 */
   app_init();
   /* USER CODE END 2 */
   ...
   /* USER CODE BEGIN 3 */
   app_loop();
   /* USER CODE END 3 */
   ```
3. `USB_DEVICE/App/usbd_cdc_if.c`:
   ```c
   /* USER CODE BEGIN INCLUDE */
   #include "usb_io.h"
   /* USER CODE END INCLUDE */
   ```
   and in `CDC_Receive_FS`, first line after `/* USER CODE BEGIN 6 */`:
   ```c
   usb_io_rx(Buf, *Len);
   ```
4. Build. Code placed between USER CODE comments survives re-generating from CubeMX.

## Verified before hardware

- The core (`rs_core.c`, `rs_baseline.c`, `rs_ml_features.c`, `rs_ml_model.h`) was run on a PC on the three
  logged drives (`tests/stm32_pc/pc_main.c`, run by `make equivalence` in `tests/`). All 454 event lines, all forest probabilities and all calibration lines
  are identical to the ESP32 firmware simulation.
- `RS_USE_ML 0` (rules only) also compiles.
- All files compile for Cortex-M4F (arm-none-eabi-gcc, `-Wall -Wextra`, no warnings) against the official
  STM32F4 HAL and USB device library headers.
- The GPS parser was checked on sample NMEA sentences (`tests/stm32_pc/gps_test.c`).
- Not yet run on the board.

## Using it

- Open the Black Pill's COM port in CoolTerm (any baud). Press `c` to recalibrate with the car still or
  on a smooth stretch, because lines printed before the port is opened are dropped.
- Keys: `p` pothole tag, `b` breaker, `r` rough, `o` other, `c` recalibrate, `s` status, `x` raw stream on/off, `?` help.
- `s` prints `#STATUS`, the forest timing (`#ML ... last=.. us`) and `#IO` counters
  (GPS sentences, I2C errors, dropped USB lines, missed samples). On a working bench all counters except
  GPS sentences should stay at 0.
- If `#I2C_ERR` lines appear with breadboard wiring, set I2C1 to Standard Mode (100 kHz) in CubeMX.
