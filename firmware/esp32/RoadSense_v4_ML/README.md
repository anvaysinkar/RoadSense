# RoadSense on ESP32

| File | What it does |
|---|---|
| `RoadSense_v4_ML.ino` | Sampling, ABC, trigger, event window, classification, serial and LittleFS logging, keys |
| `AdaptiveBaseline.h` | ABC: μ and σ per signal, slow adaptation on normal road, σ floor |
| `rs_ml_features.h` | The 21 features of one 1.4 s event window |
| `rs_ml_model.h` | The 40-tree forest as constant arrays, generated by `edge_ml/export_model.py`. Do not edit by hand |

## Build switch

```c
#define USE_ML 1   // loose trigger + forest (v4)
#define USE_ML 0   // rules only, K_LOCAL 6: the v3 detector used for the ICEdge paper
```

`ML_KEEP_PNONE` (default 0.5) trades recall for false alarms. 0.6 gives the 0.81-recall operating point.

## Flash and log

1. Install the Arduino IDE, the ESP32 core and the TinyGPSPlus library, then open this folder as a sketch.
2. Wiring:
   - MPU6050: SDA 21, SCL 22, address 0x68
   - NEO-6M: RX 16, TX 17, 9600 baud
   - Optional tag button: GPIO4 to GND
3. Open CoolTerm at **460800 baud** and capture to a file named after the vehicle (`hatchback.txt`, ...).
4. Press `c` on a smooth stretch to calibrate. The on-board LED stays on while calibrating.

Line formats and keys are in [`docs/architecture.md`](../../../docs/architecture.md).

Before trusting v4 on the road, do one short drive. Check the `Q`-line timings, and compare the event counts with the offline run (`edge_ml/compare_firmware.py`).
