# Signal chain and output protocol

The ESP32 sketch (`firmware/esp32/RoadSense_v4_ML/`) and the STM32 port (`firmware/stm32/Src/rs_core.c`) run the same chain line by line. `edge_ml/roadsense_analyze.py` and `edge_ml/rs_features.py` replay it offline in Python. `tests/` checks that all three agree.

## 1. Sampling

- MPU6050 at 100 Hz, ±4 g, DLPF 44 Hz (accel + gyro).
- NEO-6M GPS: position from RMC, satellite count from GGA, NMEA checksums verified.

## 2. Calibration (ABC)

On start-up, or when the user presses `c`:

1. **Gravity phase (1.5 s):** average the acceleration to learn the gravity direction. "Vertical" is defined from this, so the node can be mounted at any orientation.
2. **Statistics phase (6.5 s):** compute the mean μ and standard deviation σ of each signal (jerk, heave and 1 s mean jerk). σ has a floor, so a calibration done almost stationary cannot produce a near-zero threshold.
3. **Run:** μ and σ keep adapting with a slow EMA (time constant ~30 s), but only on samples classed as normal road. Potholes, breakers and rough patches never leak into the baseline.

Every threshold is `μ + k·σ` with a dimensionless `k` (`AdaptiveBaseline.h`, `rs_baseline.c`). The `k` values were tuned once on the hatchback and frozen for the sedan and SUV (`edge_ml/best_3veh.json`).

## 3. Signals

| Signal | Definition | What it catches |
|---|---|---|
| jerk | \|a(t) − a(t−1)\| | sharp impacts (pothole edges) |
| heave | 3 Hz low-pass of vertical acceleration | slow body lift (speed breakers) |
| m1s | mean jerk over the last 1 s | road roughness |

## 4. Trigger and event window

An event starts when either condition holds:

- `jerk > μ_j + K_EVENT·σ_j` **and** `jerk > K_LOCAL × m1s` (the spike stands out from the last second of road), or
- `heave > K_HEAVE_TRIG·σ_h` (gentle breakers that produce no sharp jerk).

The node then measures a fixed window from 0.2 s before to 1.2 s after the trigger: 141 samples, 1.4 s.

## 5. Classification

**Rules (v3, ICEdge):**
- `heaveDur` = time the heave stays beyond `K_HEAVE·σ_h`.
- `heaveDur ≥ 450 ms` → **BREAKER**, because a breaker lifts the whole car.
- At least 3 separate hits in the window → **ROUGHBURST**.
- Anything else → **POTHOLE**.

**Forest (v4 extension, `USE_ML 1`):**
- The trigger is loosened (`K_LOCAL` 6 → 2), so fewer real anomalies are missed.
- 21 features are computed from the same window (`rs_ml_features.h`). Amplitudes are divided by the vehicle's calibrated σ, so the model transfers between cars. Spectral band fractions, peak timing and the first heave sign are dimensionless.
- A 40-tree forest (`rs_ml_model.h`, generated by `edge_ml/export_model.py`) outputs P(BREAKER), P(NONE) and P(SURFACE).
- If `P(NONE) ≥ ML_KEEP_PNONE`, the event is dropped. Otherwise the more likely of BREAKER and SURFACE is taken.

**Roughness tier**, continuous: m1s against its baseline gives GREEN, YELLOW (`k = 2.5`) or RED (`k = 4`).

## 6. Output lines (serial)

| Line | Fields |
|---|---|
| `R` | `R,ms,ax,ay,az,gx,gy,gz`: raw 100 Hz, int16 counts. Lets every drive be re-analysed offline |
| summary | `ms,lat,lon,effectiveDelta,LABEL`: 10 Hz |
| `E` | `E,ms,lat,lon,LABEL,jerkPk_mg,jerkZ,heavePP_mg,heaveZ,heaveDurMs,nHits,hitSpanMs,firstSign` |
| `Q` | `Q,ms,pBreaker,pNone,pSurface,us`: forest output and inference time (v4 only) |
| `M` | `M,ms,lat,lon,LABEL,src`: ground-truth tag |
| `K` / `C` | calibration started / result `C,ms,mu_j,sig_j,sig_h,mu_r,sig_r,gx,gy,gz` |
| `#…` | boot, status, warnings |

## 7. Keys (CoolTerm)

| Key | Action |
|---|---|
| `p` / `b` / `r` / `o` | tag a pothole / breaker / rough patch / other |
| `c` | recalibrate on a smooth stretch |
| `s` | status, including forest timing and I/O counters |
| `x` | raw stream on/off |
| `D` | dump the flash log (ESP32) |
| `E` then `Y` | erase the flash log (ESP32) |
| `?` | help |
